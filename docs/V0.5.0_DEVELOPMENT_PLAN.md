# v0.5.0 development plan

Status: preview implementation underway; see [Milestone 4 evidence and open gates](reports/Milestone4.md) and [physical readiness](reports/E_PHYSICAL_TEST_READINESS.md). Physical execution disabled. This file establishes the
v0.5 plan in this checkout: no previous v0.5 plan was found. It carries forward
the unfinished [v0.4 hardening work](reports/SecurityAudit-0.4.md) and adds the
user-designated E: testing scope. Designating E: for testing is not authorization
for any particular physical operation.

## E:-only workstream and mandatory order

1. **Implement and test on disposable VHDX.** Extend the existing read-only
   inspector and shrink rehearsal into a helper-side, immutable-scope policy.
   Implement protected policy provenance, durable one-use confirmations,
   full-layout preview, fresh identity/raw-table checks, and operation/result
   logging. Keep the physical-disk rejection unconditional. Use synthetic data
   in `D:\PartitionManager-TestDisks` only after path/size/free-space preflight.
   Do not assign the host C/D/E letters to replica volumes. Independently verify
   primary/backup tables, protected entries and file hashes after success and
   every injected partial failure. The existing adjusted-layout rehearsal is
   historical evidence only; rerun against the exact proposed implementation.
2. **Security negative tests.** Attempt targeting every protected partition,
   boundary crossing, integer overflow, disk renumbering/substitution, cloned or
   missing identifiers, changed partition GUID/type/attributes, crafted IPC,
   forged/expired/replayed confirmations, layout changes immediately before and
   during execution, helper restart and audit failure. Every unauthorized
   request must stop before a write backend is called. Test unknown encryption,
   dirty/locked volumes, and incomplete recovery evidence as fail-closed cases.
   Commission independent review of the exact implementation and resolve every
   critical/high scope-control finding before considering physical execution.
3. **Backup and recovery readiness.** Verify a complete backup of the freshly
   identified host disk, all partitions and partition-table/boot metadata on
   separate storage outside Disk 0. Record backup identity, timestamp, coverage,
   verification log and custody; possession or a checksum alone is insufficient.
   Boot the intended recovery media in an isolated environment, restore to a
   disposable separate target, and verify restored layout, files and bootability
   as applicable. Record media hash/version, required drivers/keys, procedure,
   elapsed time, results and reviewer. Never test restore against the user's
   Disk 0. Any backup, media or restore evidence missing/stale means blocked.
4. **Physical E: test-readiness report.** Assemble evidence for the exact build,
   disk/partition IDs, original immutable extent, protected entries, exact
   operation and parameters, before/after whole-disk layout, review resolution,
   VHDX rehearsal, backup/restore readiness, interruption semantics and recovery
   instructions. Assess confinement, including shared GPT effects. Report
   each gate as verified, failed, pending or not applicable with justification.
   No operation is ready if confinement cannot be demonstrated.
5. **Stop for specific authorization.** Only after phases 1–4 pass, present the
   concrete operation, target GUIDs, exact byte changes, full layout preview,
   evidence and residual risks. Request explicit authorization for that single
   physical operation. Do not execute, enable a switch, or infer consent from
   silence, UAC approval alone, this plan, or the dedicated-testing designation.
   Any later operation needs a new confirmation and revalidation.

The dedicated [physical-test design](E_ONLY_PHYSICAL_TEST_AUTHORIZATION.md)
defines enforcement requirements. The [readiness report](reports/E_ONLY_TEST_READINESS_0.5.md)
currently says **Blocked**. No first physical operation is selected or approved.
Never initialize/erase Disk 0 or change C:, D:, EFI, MSR or recovery partitions.

## Parallel release-hardening work retained

These tasks do not depend on physical testing authorization and remain in scope:

| Work | Completion evidence |
|---|---|
| Privileged image/installation security | Protected image-root ownership and ACL checks, pinned native identity, safe DLL/extraction paths, negative substitution tests |
| Blank VHDX initialization provisioning | Protected issuer, durable one-use approval consumption, replay/restart tests; no arbitrary RAW-image approval |
| Multi-step reliability | Durable operation journal, precise uncertain/partial states, recovery verification and VM-only interruption tests |
| Installer/UAC/IPC | Isolated-VM fresh install, repair, upgrade, uninstall sentinel preservation, reinstall, accepted/declined UAC, actual pipe ACL/PID checks |
| Accessibility and UI | Keyboard/screen-reader/DPI/theme checks; exact before/after layout, accessible destructive confirmation, verified vs partial outcomes |
| Release provenance | Signing, independent review, SBOM/license review, clean-build reproducibility and verified artifact checksums |
| Move/Merge | Remain simulated/unsupported until consistent copying, metadata fidelity and recovery are demonstrated; never use E: to develop these |

Run fresh baseline/regression tests before implementation and retain failed runs.
Do not replace v0.4 evidence with unexecuted v0.5 claims. Do not bump shipped
version or publish a release merely because this plan is updated. Existing
host-installation and physical-write restrictions remain in force.
